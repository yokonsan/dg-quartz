## 重复请求，存储重复数据

```mermaid
sequenceDiagram
    participant Client
    participant Server
    participant DB

    Client->>Server: 创建订单
    Server->>DB: Create
    DB-->>Server: 成功
    Server-->>Client: 成功，网络问题客户端没收到
    Client->>Server: 重试
    Server->>DB: 重复Create
```

### 解决方案

利用数据库唯一键，添加订单号作为主键。避免重复创建。

```mermaid
sequenceDiagram
    participant Client
    participant Server
    participant DB

	Client->>Server: 获取内部订单号
	Server-->>Client: 生成返回唯一订单号
    Client->>Server: 创建订单，带上订单号
    Server->>DB: Create
    DB-->>Server: 成功
    Server-->>Client: 成功，网络问题客户端没收到
    Client->>Server: 重试，订单号一样
    Server->>DB: 重复订单号，直接返回
    DB-->>Server: 成功
    Server-->>Client: 成功
```

如果前端重新获取了订单号，业务方可加入逻辑判断，是否存在订单。

## 更新操作 ABA 情况

```mermaid
sequenceDiagram
    participant Client
    participant Server
    participant DB

    Client->>Server: 更新运单号111
    Server->>DB: Update
    DB-->>Server: 成功，运单号111
    Server-->>Client: 成功，网络问题客户端没收到
    Client->>Server: 客户发现运单填错了，更改成222
    Server->>DB: Update 222
    DB-->>Server: 成功，运单号222
    Server-->>Client: 成功
    Client->>Server: 第一次更新自动重试，运单111
    Server->>DB: Update 111
    DB-->>Server: 成功，运单号111
    Server-->>Client: 成功
```

### 解决方案

表结构加上 Version 自增字段，前端调用时带上改值。
每次调用时校验改值，版本号对不上直接返回失败。

```mermaid
sequenceDiagram
    participant Client
    participant Server
    participant DB

    Client->>Server: 更新运单号111，版本0
    Server->>DB: Update
    DB-->>Server: 成功，运单号111，版本1
    Server-->>Client: 成功，版本1，网络问题客户端没收到
    Client->>Server: 客户发现运单填错了，更改成222，版本0
    Server-->>Client: 失败，运单号111，版本0
    Client->>Server: 第一次更新自动重试，运单111 0
    Server-->>Client: 失败，运单号111，版本0
```
