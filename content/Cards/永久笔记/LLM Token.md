**Token（词元）** 是大语言模型（Large Language Model）处理文本的基本单位。

## 是什么？

在自然语言处理（[[Sources/Work/02 Wiz/Pending/NLP]]）中，文本不能直接输入给计算机，必须数字化。Token 就是文本被切分后的最小单元。

- **对于英文：** 一个 Token 通常是一个单词、单词的一部分（词根/词缀），或者是一个标点符号。
- **对于中文：** 一个 Token 通常是一个汉字，或者是常用的词组（取决于具体模型的切分策略）。
- **对于代码/数字：** 可能会被切分为特定的片段。

### 直观的例子：

（基于 OpenAI GPT-4 的分词逻辑）

- **单词：** "apple" →→ 1 个 Token
- **短语：** "red apple" →→ 2 个 Token ("red", " apple")
- **后缀：** "ing", "ed" 等常被视为单独的 Token。
- **中文：** “人工智能”
  - 在旧模型中可能被拆为：“人”、“工”、“智”、“能” (4 Tokens)
  - 在优化后的模型中可能是：“人工”、“智能” (2 Tokens) 甚至 “人工智能” (1 Token)

## Tokenization

将文本转换为 Token 的过程叫  **Tokenization**。目前主流 LLM（如 GPT 系列、Llama 系列）通常使用 **Sub-word（子词）分词算法，最常见的是 BPE (Byte Pair Encoding)**。

### 为什么要用 Sub-word？

- **如果按字符分（Character-level）：** 文本序列太长，模型难以捕捉长距离依赖，且计算量巨大。
- **如果按单词分（Word-level）：** 词汇表会无限大（英文有各种时态、复数、合成词），遇到没见过的词（OOV 问题）模型就傻了。
- **Sub-word (折中方案)：**
  - 常用词保持完整（如 "high"）。
  - 不常用词拆分（如 "unfriendly" →→ "un", "friend", "ly"）。
  - 这样既控制了词汇表大小（通常在 3 万到 10 万之间），又能组合出所有可能的词。

## Token 与 单词/字符 的换算关系

这是使用 LLM 时最常被问到的问题。不同的模型分词器（Tokenizer）不同，但有一个通用的估算标准（以 OpenAI 为例）：

- **英文：**
  - 1000 Tokens ≈≈ 750 个英文单词。
  - 平均 1 个 Token ≈≈ 4 个字符（Characters）。
  - 也就是：1 Token `≈≈` 0.75 个单词。
- **中文：**
  - 中文的转换率波动较大。
  - **早期模型（GPT-3）：** 1 个汉字往往对应 2-3 个 Token（效率低，贵）。
  - **现代模型（GPT-4o, Claude 3, 国产模型如 Qwen/DeepSeek）：** 针对中文做了优化，通常 1 个汉字 `≈≈` 0.6 ~ 1 个 Token。

## Token 对 LLM 的三大影响

理解 Token 对开发者和用户至关重要，因为它直接决定了三个核心要素：**上下文窗口、成本、性能**。

#### A. 上下文窗口 (Context Window)

模型有“记忆”限制，这个限制是以 Token 数量计算的。

- 例如 GPT-4o 的上下文是 128k Tokens。
- 这意味着你输入的提示词（Input）+ 模型生成的回答（Output）的总和不能超过这个数。
- 一旦超过，最早的信息就会被“挤出”上下文，模型会忘记你之前说过的话。

#### B. 成本 (Cost)

商业 API 通常按 Token 计费，且输入和输出价格不同。

- **Input Token（提示词）：**  较便宜（例如 $2.50 / 1M tokens）。
- **Output Token（生成词）：**  较贵（例如 $10.00 / 1M tokens）。
- **中文用户的痛点：**  如果模型对中文支持不好（分词效率低），同样一句话，中文消耗的 Token 可能是英文的 2 倍，导致使用成本翻倍。

#### C. 模型能力与局限（Token 导致的“幻觉”）

因为 LLM 是按 Token 也就是“字块”看世界的，这导致了一些奇怪的现象：

- **拼写困难：**  问模型“Strawberry 里有几个 r？”，它经常答错。因为它看到的是 token ID \[Strawberry]  这个整体，而不是  s-t-r-a-w-b-e-r-r-y  这些字母。
- **数学计算：** 对于长数字，分词可能很奇怪（如 12345 可能被分为 12 和 345），导致模型如果不使用代码解释器，直接做数学运算容易出错。

## 常见问题总结

### Q: 为什么有时候 1 个汉字 = 2 个 Token？

**A:**  这取决于模型的词汇表（Vocabulary）。如果词汇表里没有收录这个汉字，模型就会用 UTF-8 字节编码来表示它，这会占用多个 Token。国产大模型（如文心一言、通义千问）通常会扩充中文词表，使得 1 汉字 ≈≈ 1 Token 甚至更少。

### Q: 所有的 Token 都是可见的文字吗？

**A:**  不是。

- **特殊 Token：** 模型使用特殊的 Token 来标记句子的开始  \<s>、结束  \<EOS>、用户角色  \<user>  等。
- **空白符：** 空格、换行符通常也是 Token 的一部分或单独的 Token。

### Q: 同样的内容，Token 越少越好吗？

**A:**  一般来说是的。Token 越少，代表压缩率越高，意味着：

- 推理速度更快（生成的 Token 少）。
- 能塞进上下文的内容更多。
- API 调用更省钱。

## 总结

**Token 是 LLM 的“货币”和“积木”。**

- 它是模型处理信息的最小单位。
- 它是计费的依据。
- 它是限制模型记忆长度的瓶颈。
