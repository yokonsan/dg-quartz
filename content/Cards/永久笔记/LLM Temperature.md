在大型语言模型中，**Temperature（温度）**  是一个控制模型输出**随机性**和**创造性**的参数。

## 是什么？

LLM 在生成文本时，实际上是在预测下一个 [[Cards/永久笔记/LLM Token]]（字/词）的概率分布。

- **低 Temperature**：模型会变得更加**确定性**（Deterministic），倾向于选择概率最高的词。输出会更加保守、准确、连贯。
- **高 Temperature**：模型会变得更加**随机**（Stochastic），给予低概率词更多的被选机会。输出会更加多样、有创意，但也更容易出现错误或胡言乱语（幻觉）。

## 数学原理

模型在输出层会生成一组原始分数，称为 **Logits**。通常，我们使用 Softmax 函数将这些 Logits 转换为概率（总和为 1）。

引入 Temperature($T$) 后的 Softmax 公式如下：

$$
\text{Pi​}=\frac{​exp(logit_i​/T)}{\sum_{j} exp(logit_j​/T)​}​
$$

其中：

- $P_i$ 是第 $i$ 个 Token 被选中的概率。
- $logit_i$ ​是模型给第 $i$ 个 Token 打的原始分数。
- $T$ 就是 Temperature 参数。

### 产生什么效果？

假设模型预测下一个词，有两个候选词：

- "猫" (Logit = 10)
- "狗" (Logit = 5)

**情况 A：Temperature ($T$) < 1 (例如 0.5)**

- 除以小的 $T$ 会放大 Logit 的数值差异。
- 10/0.5=20,5/0.5=10。
- 经过指数运算（exp），大数变得极大，小数变得极小。
- **结果**：“猫”的概率会接近 100%，“狗”的概率接近 0%。模型变得非常自信和保守。

**情况 B：Temperature ($T$) = 1**

- 这是标准的 Softmax，保持模型原始的预测分布。

**情况 C：Temperature ($T$) > 1 (例如 2.0)**

- 除以大的T会缩小 Logit 的数值差异（使分布扁平化）。
- 10/2=5, 5/2=2.5
- 差异缩小后，经过 Softmax，“猫”和“狗”的概率差距变小了。
- **结果**：虽然“猫”还是概率最高，但“狗”被选中的几率显著增加。模型变得更不可预测。

## 效果与应用场景

通常 Temperature 的取值范围是  **0 到 2**（大多数 API 默认在 0.7 左右）。

### 🟢 低 Temperature (0.0 - 0.3)

- **特点**：
  - **确定性高**：相同的提示词几乎总是生成相同的结果。
  - **准确性高**：严格遵循逻辑和事实。
  - **枯燥**：用词单一，缺乏变化。
- **适用场景**：
  - **代码生成**（语法必须正确）。
  - **数学解题**。
  - **事实性问答**（如“中国的首都是哪里？”）。
  - **数据提取/格式化**（如从文本中提取 JSON）。

### 🟡 中 Temperature (0.4 - 0.7)

- **特点**：
  - **平衡**：在准确性和多样性之间取得平衡。
  - **自然**：对话流畅，更像人类的说话方式。
- **适用场景**：
  - **通用聊天机器人**。
  - **文章摘要**。
  - **翻译**。
  - **内容改写**。

### 🔴 高 Temperature (0.8 - 1.5+)

- **特点**：
  - **创造性强**：会使用罕见的词汇，构思新颖。
  - **不可预测**：即使同样的问题，每次回答都大不相同。
  - **风险**：容易产生“幻觉”（胡编乱造），逻辑可能不通，甚至产生语法错误。
- **适用场景**：
  - **创意写作**（写诗、写小说、编故事）。
  - **头脑风暴**（生成由不相关的概念组成的创意）。
  - **幽默/讽刺**文本生成。

## Temperature 与 [[Cards/永久笔记/LLM Top-p]]

在使用 LLM API 时，你通常会看到 Temperature 和 Top-p 两个参数。虽然它们都控制随机性，但机制不同：

- **Temperature**：改变概率分布的形状（扁平化或尖锐化）。
- **Top-p**：截断概率分布。只保留累积概率达到 $P$（例如 0.9）的前 $N$ 个词，剔除长尾的低概率词。

**比喻：** 不同概率的候选词按概率大小顺序分布在0-100的线段上，Temperature 决定不同概率词分布的线段范围区间大小，Top-p 决定候选词在线段上入围的门槛位置。

**最佳实践**：

通常建议**只调整其中一个，不要同时大幅调整两个**。

- 如果你想微调“创造力”，通常调整 Temperature 更直观。
- 如果你想在保持创造力的同时避免太离谱的错误（避免选用极低概率的词），可以使用高 Temperature 配合 0.9 左右的 Top-p。

## 建议

- **从 0 开始测试**：对于需要功能性保证的任务（如 Agent 调用工具、输出 JSON），务必将 Temperature 设为 0。
- **动态调整**：高级应用会根据用户意图动态调整 Temperature。例如，如果用户问“它的原理是什么？”，后台使用 Temp=0.2；如果用户说“给我编个笑话”，后台切换为 Temp=0.9。
- **注意模型差异**：GPT-4 在 Temp=1 时可能仍然很有逻辑，而一些较小的开源模型在 Temp=1 时可能已经开始崩坏。需要针对特定模型进行测试。
